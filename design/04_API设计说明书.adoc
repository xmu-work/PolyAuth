== 1 适用范围

本设计同时描述：

. 结构化后端的完整 RBAC3 管理 API。
. OOP 后端与结构化后端对齐的完整外部 API。
. 课程项目管理系统使用的 8 个统一身份外部 API。

两套后端共享路径、HTTP 状态码、业务码、必要响应字段和 50 个功能权限端点。

== 2 基础约定

[cols="1,3"]
|===
| 项 | 约定

| Base URL | `/api/v1`
| 结构化端口 | `8080`
| OOP 端口 | `8081`
| 字段命名 | camelCase
| 管理端响应 | `Result { code, message, data?, requestId?, timestamp }`
| 分页响应 | `PageResult { total, page, pageSize, list }`
| 分页请求 | `page` 从 1 开始；`size` 默认 20，最大 100
| 时间 | ISO 8601 本地时间，例如 `2026-11-22T20:00:00`
| 主键 | `Long` JSON 数字
| 统一身份用户标识 | `iam_user.user_no` 字符串
|===

统一身份 8 个接口不使用管理端 `Result` 包装。成功直接返回业务对象，失败返回
`{code: string, message: string}`。

== 3 认证与授权

=== 3.1 管理端

管理端请求携带：

[source,text]
----
Authorization: Bearer <accessToken>
----

认证成功后，双后端均执行以下默认拒绝流程：

. 以 Controller 路径模板和 HTTP 方法查询 `iam_api`。
. 检查 API 是否映射到前端权限。
. 检查当前用户在 `ADMIN` 系统是否具有该权限。
. 未登记、未映射或无权限均返回 HTTP 403，业务码 2007。

`/auth/*` 接口只要求认证，不参与管理端 `iam_api` 功能权限映射。统一身份查询自身仍需
满足业务权限，例如 `/auth/users/{userId}` 要求目标系统 `TEC` 权限。

=== 3.2 OpenAPI

`/open/**` 支持：

* 普通用户 Bearer 令牌：只允许访问当前用户本人。
* 接入方签名：请求头 `X-App-Id`、`X-Timestamp`、`X-Nonce`、`X-Signature`。

签名时间偏差、nonce 防重放和接入系统状态错误分别使用 2009、2010、2011。

=== 3.3 写请求保护

* `X-Request-Id` 由请求过滤器校验或生成，并回写响应头与 `Result.requestId`。
* `Idempotency-Key` 对 POST、PUT、DELETE、PATCH 生效。
* 同一调用者、同一键、同一请求重放首次成功响应。
* 同一键用于不同请求返回 HTTP 409 / 1004。

== 4 请求格式

=== 4.1 JSON Body

[cols="1,2,1"]
|===
| 方法 | 路径 | 请求体

| POST | `/auth/login` | 登录对象
| PUT | `/roles/{roleId}` | `UpdateRoleDTO`
| POST | `/roles/{roleId}/permissions` | 权限主键裸数组
| DELETE | `/roles/{roleId}/permissions` | 权限主键裸数组
|===

角色更新固定使用 JSON：

[source,json]
----
{
  "roleName": "课程管理员",
  "description": "更新说明",
  "status": "ACTIVE",
  "parentId": 3
}
----

=== 4.2 Query/Form

其余写接口使用 `@RequestParam`，或由 Spring 从 query/form 参数绑定 DTO。前端使用
`postForm`、`putForm`、`deleteForm`。不得把 DTO 表单入口统一发送成 JSON 对象。

== 5 统一身份外部 API

[cols="1,3,1"]
|===
| 方法 | 路径 | OOP 状态

| POST | `/auth/login` | 已实现
| POST | `/auth/logout` | 已实现
| GET | `/auth/me` | 已实现
| GET | `/auth/permissions/{permission}` | 已实现
| GET | `/auth/departments` | 已实现
| GET | `/auth/api-permissions/{operationId}` | 已实现
| GET | `/auth/departments/{departmentId}/users` | 已实现
| GET | `/auth/users/{userId}` | 已实现
|===

登录响应中的 `userId` 为本地数据库主键字符串，是管理后台兼容字段。统一身份用户标识使用
JWT `sub` 或 `/auth/me.subject`，值为 `user_no`。`/auth/users/{userId}` 使用 `user_no`。

`operationId` 对应目标系统内的 `iam_api.api_code`：

* API 不存在：HTTP 404 / `API_OPERATION_NOT_FOUND`。
* API 存在但未映射权限或无权限：HTTP 200 / `allowed=false`。

== 8 双后端契约

当前共享黑盒场景覆盖：

* 未认证访问返回 401/2001。
* 登录后查询角色。
* 不存在角色返回 404/1005。
* 重复角色编码返回 409/3009。
* 角色继承成环返回 409/3002。
* 过期临时授权返回 400/1001。
* 令牌校验失败使用数字 2001。
* 不存在的 operationId 使用 `API_OPERATION_NOT_FOUND`。

两套后端注册相同的外部端点。执行双后端测试前需分别启动 8080 和 8081，
并使用相同 schema/seed 基线；真实 MySQL 契约脚本通过后才能作为现场运行结论。
