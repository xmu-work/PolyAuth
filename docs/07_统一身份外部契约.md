# 统一身份外部契约（课程项目管理系统）

## 1. 适用范围

本契约替换旧的 `/open/authorize`、`POST /open/authorize/batch` 对外鉴权入口。
课程项目管理系统只依赖下列 10 个接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | 账号密码登录并签发 JWT |
| POST | `/api/v1/auth/logout` | 吊销当前 JWT，返回 204 |
| GET | `/api/v1/auth/me` | 当前用户、角色与前端权限码 |
| GET | `/api/v1/auth/permissions/{permission}` | 校验指定前端权限码 |
| GET | `/api/v1/auth/departments` | 按层级分页查询部门 |
| GET | `/api/v1/auth/api-permissions/{operationId}` | 按 operationId 校验 API 权限 |
| GET | `/api/v1/auth/departments/{departmentId}/users` | 分页查询部门用户 |
| GET | `/api/v1/auth/users/{userId}` | 按统一身份用户标识查询姓名与工号 |
| GET | `/api/v1/auth/audit-logs` | 按操作人、操作对象与时间范围分页查询外部业务审计日志 |
| POST | `/api/v1/auth/audit-logs` | 按 `requestId` 幂等写入外部业务审计日志（201 Created） |

这 10 个接口不使用内部 `Result {code,message,data,timestamp}` 包装，也不使用内部数字错误码。
成功响应直接返回业务对象；错误响应格式为：

```json
{
  "code": "UNAUTHORIZED",
  "message": "请先登录"
}
```

## 2. 登录与 JWT

登录请求：

```json
{
  "username": "20220101",
  "password": "password",
  "systems": ["course-project-management"]
}
```

`systems` 必填、不可为空且不可重复。首个系统作为当前访问上下文，全部系统写入 JWT
`aud`。`sub` 使用统一身份用户标识，即本系统的 `iam_user.user_no`。

成功响应：

```json
{
  "accessToken": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 7200,
  "userId": "1",
  "displayName": "张小雨",
  "accountStatus": "NORMAL"
}
```

前三个字段是外部契约必需字段；`userId`、`displayName`、`accountStatus`
是管理后台兼容字段，外部系统可以忽略。`userId` 是本地数据库主键字符串，
不是统一身份用户标识。统一身份用户标识使用 JWT `sub` 或 `/auth/me.subject`；
调用 `/auth/users/{userId}` 时必须传统一身份用户标识，即 `iam_user.user_no`，
不能直接使用登录响应中的本地 `userId`。

## 3. 权限语义

- `/auth/me` 的 `roles` 取值限定为 `student / teacher / admin`。
- 角色编码包含 `student`、`teacher`、`admin` 时分别映射到对应外部角色。
- `permissions` 返回目标系统 `iam_permission.permission_code`，不返回内部主键。
- `/auth/permissions/{permission}` 只返回 `{"allowed": boolean}`。
- `/auth/api-permissions/{operationId}` 使用 `iam_api(api_code)` 定位 API，再检查其映射的前端权限。
- API 不存在时返回 404 / `API_OPERATION_NOT_FOUND`。
- API 存在但未映射权限或无权限时返回 200 / `allowed=false`。
- `/auth/users/{userId}` 需要目标系统的 `TEC` 权限，否则返回 403 / `FORBIDDEN`。

## 4. 部门与用户

部门响应分页字段为 `page / pageSize / total / items`。`parentId` 为空时查根部门，
传入时只查直接下级；`hasChildren` 用于前端逐层展开。

部门用户和用户详情只返回统一身份所需的最小字段：

```json
{
  "userId": "T1008",
  "no": "T1008",
  "name": "孙晨",
  "departmentId": 1,
  "departmentName": "计算机学院"
}
```

不返回手机号、邮箱、密码、密文或内部脱敏字段。

## 5. 统一身份外部审计日志（`/auth/audit-logs`）

外部审计日志复用只追加表 `iam_log`，以 `log_type = 'ACTION'` 与 `decision_id = 'EXT_AUDIT'` 与内部管理端 HTTP 访问日志隔离，无需改动数据库表结构：

- **`POST /api/v1/auth/audit-logs`**：
  - 请求体：`{ requestId, type, objectType, objectId, target, before, after }`；
  - 任意已登录活跃用户均可写入（满足教师、管理员及学生建组等业务场景），操作人固定取 JWT 当前用户；
  - 以 `(system_code, 'EXT_AUDIT', requestId)` 作为持久化幂等键，重复提交直接返回原记录，返回 `201 Created` 与裸日志对象 `{ id, at, actor, type, target, before, after, termId, courseId, classId }`；
  - 完整 `target`（最长 500 字符）及 `objectType/objectId/termId/courseId/classId` 保存在 `iam_log.detail` JSON 中，`iam_log.target` 列按 255 字符截断保存。
- **`GET /api/v1/auth/audit-logs`**：
  - 支持参数：`actor`（操作人姓名或工号模糊匹配）、`actorId`、`target`（操作对象摘要模糊匹配）、`from` / `to`（ISO-8601 带时区时间，按 `Asia/Shanghai` 对齐）、`page`（默认 1）、`pageSize`（默认 20，最大 100）；
  - 要求当前用户在目标系统具备 `AV` / `MLG` 权限码或外部角色包含 `admin` / `teacher`，否则返回 `403 / FORBIDDEN`；
  - 返回裸分页对象 `{ page, pageSize, total, items }`；`actor` 保留已软删除历史操作人姓名并标记 `deleted: true`。

## 6. 数据库初始化与升级

全新数据库按顺序执行：

```text
backend/src/main/resources/db/schema.sql
backend/src/main/resources/db/seed.sql
```

已初始化数据库执行幂等升级脚本：

```text
backend/src/main/resources/db/identity_course_upgrade.sql
```

该脚本登记 `course-project-management` 系统、`teacher / student / admin`
角色和 `TEC` 权限，不覆盖已有业务权限。
